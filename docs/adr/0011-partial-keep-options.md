# ADR-0011: `partial` の `keep` は「残す条件」であり、満たさなければ全て伏せる

- ステータス: Accepted
- 日付: 2026-08-14
- 関連: [ADR-0003](./0003-config-file-design.md), [ADR-0004](./0004-output-formats.md), [ADR-0009](./0009-mask-null-strength.md)

## コンテキスト

[ADR-0003](./0003-config-file-design.md) §9 は `partial` を「一部を残す（`keep: domain` / `keep_prefix: N` / `keep_suffix: N`）」とだけ定め、**詳細仕様を未決事項に置いていた。** #4 で適用エンジンを実装するにあたり、決めなければ動かない点が4つ出た。

1. `keep: domain` で `@` が無い値、あるいは `@` の後ろがドメインに見えない値をどうするか
2. `keep_prefix` / `keep_suffix` が値の長さ以上のときどうするか
3. 同じ列に `partial` のルールが複数マッチし、`keep` の指定が食い違ったらどうするか
4. `keep` 系を `partial` 以外の method に書いたらどうするか

`partial` は**唯一「値の一部を出力に残す」方法**である。他の方法（`redact` / `hash` / `null` / `drop`）はどう転んでも元の値が出ない。判断を誤ったときに素の値が出るのはここだけなので、細部まで決める。

## 決定

**`keep` の指定は「残してよい条件」として読む。条件を満たさない値は全て伏せる。**

### 1. `keep: domain` は `@` の後ろがホスト名の形をしているときだけ残す

```
user@example.com          → ****@example.com
user@日本語.jp             → ****@日本語.jp
notanemail                → ****
送付先は bob@example.com、案件は #4471 です  → ****
連絡先: @taro_handle       → ****
user@localhost            → ****
```

ホスト名の形とは、ドットで区切られた2つ以上のラベルがあり、各ラベルが英数字・`-`・`_` だけからできていることとする。

**列がメールアドレスだけを持つとは限らない。** `*mail*` のようなパターンは `mail_body` や `contact_note` にも掛かる。`@` の後ろを無条件に残すと、自由記述の本文が丸ごと出る。上の4つ目がその例で、`@` 以降には「案件は #4471 です」まで含まれる。

ドットを必須にしたのは、`@taro_handle` のような SNS のメンションを弾くため。1ラベルの並びを通すと、自由記述に混ざったハンドル名がそのまま残る。**代償として `user@localhost` のような TLD の無いアドレスもドメインを残せなくなる。** どちらか一方しか選べないので、残さない側に倒す。

`@` が複数ある値では最後の `@` を境にする。メールアドレスのローカル部には引用形式で `@` を書けるため。

### 2. 残す文字数が値の長さ以上なら全て伏せる

```
keep_prefix: 4 に "abc"    → ****
keep_prefix: 2 に "abcdef" → ab****
keep_prefix: 2, keep_suffix: 2 に "abcd" → ****
```

`keep_prefix: 4` の列に3文字の値が来たときに、**素の値がそのまま出るのを防ぐ。** 「4文字残す」は「4文字までなら見せてよい」の意味であって、「値が短ければ全部見せてよい」ではない。

文字数はルーンで数える。バイトで数えると多バイト文字の途中で切れる。

伏せ字は長さによらず `****` に固定する。元の長さに合わせて伸縮させると、長さそのものが手掛かりになる。

### 3. `partial` が複数マッチしたら、両方が残す部分だけを残す

```yaml
# 共有設定
- patterns: ["*email*"]
  method: partial
  keep: domain

# ローカル設定
- patterns: ["user_email"]
  method: partial
  keep_prefix: 1
```

`user_email` には両方がマッチする。強さは同じ `partial` なので、[ADR-0009](./0009-mask-null-strength.md) の強度順序では決まらない。

**どちらか一方を選ばない。** 選ぶと、もう片方が隠すつもりだった部分が出る。`keep_prefix` は小さい方を採り、`keep: domain` は両方が指定したときだけ残す。上の例では `keep_prefix: min(0, 1) = 0`、`domain` は片方だけなので残さず、結果は `****` になる。

この規則には、**ルールを足しても出る情報が増えないという性質**がある。マスクルールのマージが和集合であること（ADR-0003 §7）と噛み合う。追加が弱化になる経路を残さない。

### 4. `keep` 系を `partial` 以外の method に書いたらエラー

```yaml
- patterns: ["email"]
  method: none          # partial の書き忘れ
  keep_prefix: 3
```

これを黙って通すと、`keep_prefix: 3` は無視され、列は**丸ごと素通りする。** 書いた側は「先頭3文字だけ見せる」つもりでいる。

`method: partial` に `keep` 系が1つも無い場合も同じくエラーにする。何も残さない `partial` は `redact` と同じであり、書き間違いの可能性の方が高い。

## 検討したが採用しなかった選択肢

**`keep: domain` で `@` の後ろを常に残す** — 実装は最も単純。採らなかったのは上述のとおり、自由記述の列に掛かったときに本文が出るため。「メールアドレスの列にしか書かないはず」という前提は、パターンがグロブである以上保証できない。

**`keep: domain` でメールアドレスの形を厳密に検証する（RFC 5322）** — 過剰。判定の複雑さに対して得るものが少なく、厳密な検証を通らないアドレスでドメインが出なくなる方向の食い違いが増える。**残す条件としては緩くても、緩さは「残さない側」にしか効かない**ため、ホスト名の形だけを見る。

**残す文字数が値の長さ以上なら、そのまま値を出す** — `keep_prefix: 4` に3文字の値で `abc` が出る。短い値ほど素で出るという、最も避けたい振る舞いになる。

**`partial` が複数マッチしたら設定エラーにする** — 追加が実行を止める経路になる。共有設定とローカル設定の書き手は互いを知らず、ADR-0003 §7 の和集合マージと噛み合わない（[ADR-0009](./0009-mask-null-strength.md) で `null` と `redact` の衝突について同じ判断をしている）。

**後に書かれたルールを優先する** — レイヤの並び（ユーザ設定 → 共有設定 → ローカル設定）で結果が変わる。ローカル設定が共有設定の `keep` を上書きできることになり、弱化の経路になる。

## 結果

**得られるもの**

- `partial` で素の値が出る経路が塞がる。値が短くても、列が自由記述でも、ルールが複数あっても
- ルールを足しても出る情報が増えない。和集合マージの前提が `partial` の内側でも成り立つ
- `keep` の書き間違いが実行前にエラーになる

**支払うコスト・受け入れる制約**

- **`user@localhost` のような TLD の無いアドレスでドメインを残せない。** ドットの必須化と引き換えに受け入れる
- **`partial` が複数マッチすると、どちらの指定とも違う結果になりうる。** 上の例では両方が「一部を残す」と書いているのに `****` が出る。サマリ（ADR-0004 §5）には `partial` としか出ないため、なぜ何も残らなかったかは設定を読まないと分からない
- 残す文字数の指定が値によって効いたり効かなかったりする。同じ列でも行によって `ab****` と `****` が混ざる

## 未決事項

- `keep` に `domain` 以外の値（`local` / `last4` 等）を足すか。要求が出てから決める
- サマリに「指定した `keep` が効かなかった」ことを出すか。stderr への出力（#5）と一緒に決める
