# ADR-0009: マスク方法 `null` の強度は `redact` と `hash` の間に置く

- ステータス: Accepted
- 日付: 2026-08-14
- 関連: [ADR-0003](./0003-config-file-design.md), [ADR-0004](./0004-output-formats.md), [ADR-0006](./0006-mask-method-null-quoting.md)

## コンテキスト

[ADR-0003](./0003-config-file-design.md) §7 は、1つの列に複数のマスクルールがマッチしたとき**最も強い方法が勝つ**と決め、強さの順序を次のように書いている。

```
drop > redact > hash > partial > none
```

**この並びに `null` が無い。** ADR-0003 §9 と [ADR-0004](./0004-output-formats.md) §3 は `null`（`NULL` に置換。型を保ちたいときに使う）をマスク方法の一つとして定義しているため、順序の側だけが欠けている。

[ADR-0006](./0006-mask-method-null-quoting.md) はこれを未決事項として挙げ、「失われる情報量で言えば `null` は `redact` に近いが、`redact` との優劣は実装の文脈がないと決められない」として #4（適用エンジン）に持ち越した。適用エンジンは列ごとに1つの方法を選ばなければ動かないため、ここで決める。

決めるべきなのは実質的に2点である。

1. `null` と `hash` / `partial` の優劣
2. `null` と `redact` の優劣

## 決定

**`redact` と `hash` の間に置く。**

```
drop > redact > null > hash > partial > none
```

### `null` は `hash` より強い

`hash` は同じ値が同じハッシュになる（ADR-0003 §9）。これは件数集計や JOIN を可能にするための性質であり、裏返せば**行の間の等値関係が出力に残る**ということである。低カーディナリティの列では値の分布もそのまま出る。`null` は等値関係も分布も残さない。失われる情報量は `null` の方が大きい。

### `null` は `redact` より弱い

情報量では差が付かない。`sumiq` は値が NULL かどうかを見ずにマスクを適用するため、`redact` を掛けた列は全ての行が `****` になり、`null` を掛けた列は全ての行が `NULL` になる。どちらも元の値について何も残さない。

そこで**読み違えの起きにくさ**で決めた。`****` は「隠されている」と見て分かる。`NULL` は**「取得したが値が無かった」と読める**。`csv` では空フィールドになり、空文字列とも区別が付かない（ADR-0004 §3）。

ADR-0004 §3 は `drop` について、値だけ空にして列名を残すと「取得したが空だった」と誤読されるという理由で、ヘッダからも消すことを決めている。`null` と `redact` が並んだときに `NULL` を選ぶのは、これと同じ誤読を招く側を選ぶことになる。

複数のルールがマッチするのは、**片方の書き手がもう片方を知らないとき**である。そこで「型を保ちたい」という利便性の指定が、「伏せ字で隠す」という指定に勝つ理由は無い。

### この決定は ADR-0003 §7 の並びを変えない

`null` を既存の並びに挿入しただけで、既存の5つの相対順序は変えていない。ADR-0003 §7 の記述は有効なまま残る。

## 検討したが採用しなかった選択肢

**`null` を `redact` より強くする** — 「型を保つ」という追加の制約が付く分だけ弱い、とも読める。採らなかったのは上述の誤読の問題に加えて、`csv` で空フィールドに落ちるためである。最も強いマスクが、形式によっては最も見分けの付かない出力になる。

**`null` と `redact` が同時にマッチしたらエラーにする** — 決めきれないものを利用者に押し付ける案。採らない。マスクルールは全レイヤの和集合であり（ADR-0003 §7）、共有設定とローカル設定の書き手は互いを知らない。**ルールを足しただけで実行が止まる**のは、追加が安全であることを前提にした和集合マージと噛み合わない。

**`null` を強度順序から外し、`redact` 等と同時にマッチしたら `null` を無視する** — 実質的に最弱として扱う案。`hash` にも負けるため、`null` を書いた列に `hash` のルールが後から掛かると等値関係が復活する。弱化の経路になるため採らない。

## 結果

**得られるもの**

- 適用エンジンが列ごとに1つの方法を決められる。ADR-0006 の未決事項が閉じる
- 全ての方法が全順序になり、マッチしたルールの並び順に結果が依存しなくなる
- どの組み合わせでも、勝った方法は負けた方法以上に情報を消す

**支払うコスト・受け入れる制約**

- **`method: "null"` は `redact` に負ける。** 型を保ちたくて `null` を書いた列に、別のレイヤから `*memo*` のような広いルールで `redact` が掛かると、型は保たれない。ADR-0004 §3 が「マスクされた列の値は常に文字列」と決めている以上、型の保存はもともと `null` を単独で使えた場合に限る性質である
- 「強い」の意味が2つの尺度（失われる情報量と、誤読の起きにくさ）にまたがる。`null` と `redact` の比較にだけ後者が効いており、順序の根拠が一様でない

## 未決事項

- **`hash` が出すハッシュの文字数**（ADR-0003 §9 の「先頭 N 文字」の N）。実装では 12 文字（16 進、48 ビット）に固定した。`max_rows` が 1000 前後である以上、1回の実行内で衝突する確率は無視できる。設定項目にはしていない。要求が出てから決める
